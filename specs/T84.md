## Rules that are not obvious

1. Rank: `NOT_MENTIONED` and `GAP` = 0, `PARTIAL` = 1, `VERIFIED` = 2. `meets(s, m)` is
   `rank(s) >= rank(m)`; a missing status counts as `NOT_MENTIONED`.
2. `load_job_profiles` reads `<pack root>/job_profiles/*.json` in sorted file order. It raises
   `ContentPackError` naming the file when:
   - the JSON is invalid;
   - a `node_id` is not in the pack's curriculum;
   - a node appears twice in one profile;
   - two files share a `job_id`.
3. `qualified` is true when every **required** node meets its `min_status`. Adjacent nodes never
   block it.
4. With `job_profile`, the selector:
   - considers only the profile's nodes;
   - treats a node as done when it meets its `min_status` (so an adjacent `PARTIAL` node is not
     taught further);
   - walks every required node before any adjacent node, keeping the existing order (breadth-first
     or depth-first) inside each group.
   - Parked handling is unchanged.
   - Without `job_profile`, behaviour is byte-for-byte what it is today.
5. The seed profile is fictional: `job_id` `revenue_accountant_seed`, title "Revenue accountant
   (seed profile, fictional)", sector "IT services".
   - About six required nodes from steps 1 to 5 of `ind_as_115`: `VERIFIED` on the level-1 steps,
     `PARTIAL` on one level-2 node.
   - Two adjacent nodes at `PARTIAL`.
   - Use only node IDs that exist in `concept_map.json`.
